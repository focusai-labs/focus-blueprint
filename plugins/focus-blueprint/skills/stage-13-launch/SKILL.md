# שלב 13: רשימת השקה

בכל מקום שכתוב `bp`, מריצים `node "${CLAUDE_PLUGIN_ROOT}/scripts/bp.mjs"`.

## למה השלב הזה קיים

השקה טובה מגלה את הבעיות לפני הלקוח. שוברים בכוונה, לפני שמישהו ישבור בטעות: בודקים שלקוח אחד לא רואה לקוח אחר, שאין סוד בדפדפן, ושיש התראה כשמשהו נופל. כל שורה ברשימה נסגרת עם ראיה, ולא עם "נראה בסדר".

## מה קוראים לפני שמתחילים

- בקובץ המצב `.blueprint/state.json`, השלב הנוכחי הוא 13, והמסלול.
- שלבי המסלול לשלב 13, בקובץ `${CLAUDE_PLUGIN_ROOT}/data/tracks/<track>.json`.
- הממצאים מבדיקת השמישות בקובץ `spec/usability-test.md`, ודוח הסקירה `spec/ux-review.md`.

## מה עושים

1. מריצים `bp stage start 13`.
2. כותבים את `docs/critical-points.md`: מה שוברים בכוונה, ומה צריך לקרות כשזה נשבר. למשל משתמש שני שמנסה לקרוא נתונים של אחר, שליחה כפולה, רשת שנופלת באמצע, ומפתח שחסר.
3. עוברים על רשימת ההשקה, וכותבים ליד כל שורה את הראיה ב-`docs/launch-checklist.md`:
   - **בידוד נתונים**: משתמש שני לא רואה אף שורה של הראשון, בבדיקה חיה.
   - **אבטחה**: `get_advisors` מסוג security ומסוג performance נקיים.
   - **סודות**: אין מפתח סודי בקוד שמגיע לדפדפן, ומשתני הסביבה קיימים ב-Vercel.
   - **דומיין**: הדומיין מחובר לפי שלבי המסלול, דרך `/focus-blueprint:docs-verify`.
   - **התראה**: יש התראה כשמשהו נופל, לפי הצומת שנבחר.
   - **חוויית משתמש**: `/focus-blueprint:ux-review` על כל המערכת החיה, וכל ממצא מבדיקת השמישות סגור.
   - **גיבוי**: יש גיבוי, ויודעים איך חוזרים ממנו.
   - **חזרה אחורה**: יודעים איפה הכפתור שמחזיר ב-Vercel לגרסה הקודמת, ומה קורה אחריו.
4. שוברים בכוונה כל נקודה במפת הנקודות הקריטיות, ובודקים שקרה מה שצריך לקרות.
5. כשהכל מוכח, מסמנים שהמערכת באוויר: `bp state set live=true`. מאז כל מיגרציה רק מוסיפה, וה-hook חוסם מחיקה.

## מה חייב להיות נכון בסוף (ההוכחה)

- בקובץ `docs/launch-checklist.md` יש ראיה לכל שורה.
- כל נקודה בקובץ `docs/critical-points.md` נשברה בכוונה, והתוצאה כתובה.
- הסגירה עוברת דרך `/focus-blueprint:verify`, והפלט שלה מצוטט.

## מה נשאר בתיקייה

- הקבצים `docs/launch-checklist.md` ו-`docs/critical-points.md`
- הדגל `live` בקובץ המצב

## סגירה

1. מריצים את `/focus-blueprint:verify` ואת בדיקות ההוכחה, ושומרים את הפלט האמיתי.
2. מציגים את ההכרעות של השלב: `bp ruling list --unreported --stage 13`, ואז `bp ruling report --stage 13`.
3. סוגרים: `bp stage done 13 --status <done|done_with_concerns|blocked|needs_context> --note "<מה פתוח>" --proof "<הפלט>"`. כששורה ברשימה התקבלה עם פער ידוע, הסטטוס הוא `done_with_concerns`, והפער כתוב בהערה.
4. עושים commit בענף `stage-13` עם הודעה בעברית, PR, ומיזוג אחרי שהבדיקה עוברת.
5. כותבים את `.blueprint/last-session.md`.
6. אומרים לסטודנט בשורה אחת כנה איך השלב נסגר. אחר כך שתי שורות: הבא בתור הוא הסליקה אם הוחלט עליה, או המסירה, בשיחה חדשה עם `/blueprint`.
