# בדיקת פערים

בכל מקום שכתוב `bp`, מריצים `node "${CLAUDE_PLUGIN_ROOT}/scripts/bp.mjs"`.

לפעמים משנים משהו ישירות בלוח של Supabase או בתוך workflow ב-n8n, והמסמכים לא יודעים על זה. הבדיקה הזאת מוצאת את הפערים, ולא משאירה שינוי שאף אחד לא יודע עליו.

## Supabase

1. מושכים את רשימת הטבלאות דרך ה-MCP של Supabase, עם `list_tables`.
2. משווים לטבלאות במפה `.blueprint/map.json`.
3. מסמנים כל טבלה שנוספה מחוץ למפה, כל טבלה שחסרה, וכל טבלה שהשתנתה.

## n8n

1. קוראים את כתובת ה-n8n מקובץ המצב, בשדה `where.n8nBase`. את מפתח ה-API קוראים מהקובץ `.env.local` בלבד, ולא שומרים אותו בשום מקום אחר. כשהמפתח לא שם, אומרים לסטודנט להוסיף אותו לקובץ הזה.
2. מושכים את רשימת ה-workflows מה-API הרשמי של n8n, עם הכותרת `X-N8N-API-KEY`.
3. משווים לעותקים בתיקייה `n8n`: מספר ה-nodes והשמות שלהם.

## מה עושים עם הפערים

1. מציגים דוח קצר: מה נוסף מבחוץ, מה חסר, ומה השתנה.
2. שואלים על כל פער: לרשום אותו במפה, או לבטל אותו. ביטול שמוחק נתונים הוא אחת מארבע העצירות, ולכן הוא תמיד באישור מפורש.
3. רושמים במפה את מה שהוחלט לשמור, ומעדכנים את העותק בתיקייה `n8n`.
4. מעדכנים את התאריך: `bp state set lastDriftCheck=<התאריך והשעה עכשיו>`.

## מה חייב להיות נכון בסוף

- הדוח הוצג לסטודנט, ולכל פער יש החלטה.
- השדה `lastDriftCheck` בקובץ המצב מראה את התאריך של היום.
