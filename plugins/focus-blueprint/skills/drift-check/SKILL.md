# בדיקת פערים

בכל מקום שכתוב `bp`, מריצים `node "${CLAUDE_PLUGIN_ROOT}/scripts/bp.mjs"`.

המפה והמסמכים נשמרים במאגר יחד עם הקוד, והם אמורים לתאר בכל רגע את המערכת שרצה (Living Specifications). לפעמים משנים משהו ישירות בלוח הבקרה של Supabase או בתוך workflow ב-n8n, והשינוי לא נכנס למסמכים. מאותו רגע המסמכים כבר לא מתארים את המערכת (Documentation Drift). הבדיקה הזאת מוצאת את הפערים האלה, כדי שלא יישאר שינוי שאף אחד לא יודע עליו.

## Supabase

1. מושכים את רשימת הטבלאות דרך ה-MCP של Supabase, עם `list_tables`.
2. משווים אותה לטבלאות במפה `.blueprint/map.json`.
3. מסמנים כל טבלה שנוספה מחוץ למפה, כל טבלה שחסרה וכל טבלה שהשתנתה.

## n8n

1. קוראים את הכתובת של ה-n8n מקובץ המצב, בשדה `where.n8nBase`. את מפתח ה-API קוראים רק מהקובץ `.env.local`, ולא שומרים אותו בשום מקום אחר. אם המפתח לא נמצא שם, מבקשים מהסטודנט להוסיף אותו לקובץ הזה.
2. מושכים את רשימת ה-workflows מה-API הרשמי של n8n, עם הכותרת `X-N8N-API-KEY`.
3. משווים אותה לעותקים בתיקייה `n8n`, לפי מספר ה-nodes והשמות שלהם.

## הדוח

בדוח כותבים רק את הפערים. כשאין אף פער, כותבים שורה אחת שאומרת שלא נמצאו פערים. כל פער נכנס לאחד מארבעה סוגים:

| הסוג | מה זה אומר כאן |
|---|---|
| חסר (Missing Features) | טבלה או workflow שרשומים במפה ולא קיימים במערכת |
| מודל חלקי (Incomplete Models) | טבלה שקיימת בשני המקומות, אבל העמודות שלה שונות |
| קיצור בלוגיקה (Logic Shortcuts) | workflow שה-nodes שלו שונים מהעותק בתיקייה `n8n` |
| סטייה מהמבנה (Architectural Divergence) | טבלה או workflow שקיימים במערכת ולא רשומים במפה |

## מה עושים עם הפערים

1. מציגים את הדוח לסטודנט.
2. על כל פער הסטודנט מחליט מה מתקנים: את המסמכים ואת המפה, כדי שיתארו את מה שקיים, או את המערכת, כדי שתחזור למה שכתוב (Two-Way Reconciliation). Claude ממליץ ומסביר את המחיר של כל אפשרות, והסטודנט מחליט. ביטול שמוחק נתונים הוא אחת מארבע העצירות, ולכן תמיד מבקשים עליו אישור מפורש.
3. כשמחליטים לשמור משהו שנוסף מבחוץ, פותחים עליו שינוי עם `/focus-blueprint:change`, כדי שהממדים שהוא פותח ייבדקו כמו בכל שינוי אחר. את מה שהוחלט רושמים במפה רק דרך הפקודות של `bp`, ומעדכנים את העותק בתיקייה `n8n`. כשהמפה השתנתה, מריצים `bp render`.
4. מעדכנים את תאריך הבדיקה עם `bp state set lastDriftCheck=<התאריך והשעה עכשיו>`.

## מה חייב להיות נכון בסוף

- הדוח הוצג לסטודנט, ולכל פער יש החלטה.
- השדה `lastDriftCheck` בקובץ המצב מראה את התאריך של היום.
