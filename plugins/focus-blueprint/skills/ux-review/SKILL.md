# סקירת UX

בכל מקום שכתוב `bp`, מריצים `node "${CLAUDE_PLUGIN_ROOT}/scripts/bp.mjs"`.

מסך יפה עוד לא אומר שאפשר להשתמש בו. את מה שאפשר למדוד, סקריפט מודד. את השאר Claude סוקר על צילומי מסך, לפי רשימת עקרונות. העקרונות ברמה `must` עוברים לפני שאדם אמיתי רואה את המסך.

## מה סוקרים

- כשלא נאמר אחרת: כל המסכים במפה `.blueprint/map.json`. בשלב 7 דרך הקישור ל-mockup או דרך `file://`, ובשלבים 11 עד 13 דרך הכתובת החיה.
- כשמגיעים מתוך יכולת בשלב 12: רק המסכים של היכולת הזאת.

## איך סוקרים כל מסך

1. קוראים עם הכלי Read את הקובץ `${CLAUDE_PLUGIN_ROOT}/scripts/ux-check.browser.js`. הטקסט שלו הוא פונקציה אחת.
2. בכלי ה-MCP של Playwright: `browser_navigate` לכתובת, `browser_resize` לרוחב 1280 ולגובה 800, ואז `browser_evaluate` עם הטקסט של הקובץ בשדה `function`. שומרים את התוצאה.
3. אותו דבר ברוחב 390 ובגובה 844. בדיקות שמסומנות לטלפון בלבד או למחשב בלבד מדלגות לבד ברוחב השני.
4. מצלמים את המסך בשני הרוחבים עם `browser_take_screenshot`, ושומרים בתיקייה `spec/ux`.
5. עוברים על כל עיקרון בקובץ `${CLAUDE_PLUGIN_ROOT}/data/ux/principles.json` שהשדה `check` שלו הוא `review`, ושהשלב הנוכחי נמצא ברשימת השלבים שלו. לכל אחד שופטים על הצילומים, ונותנים פסק דין בשורה אחת: עבר, נכשל או אזהרה, ולמה.
6. כשאין Playwright MCP, או שהדפדפן תפוס, אומרים את זה בגלוי. הסקירה לא נחשבת כאילו עברה.

## מה עושים עם התוצאות

1. כל `must` שנכשל, בבדיקה האוטומטית או בסקירה, מתקנים במקום, ומריצים שוב את המסך. ממשיכים עד שאין `must` שנכשל.
2. כל `should` שלא מתקנים עכשיו נכנס לרשימת "אחר כך" עם הסיבה: `bp map later add "<העיקרון, המסך והסיבה>" --stage <השלב>`.
3. כותבים את `spec/ux-review.md`: טבלה עם העיקרון, הרמה, אוטומטי או סקירה, התוצאה בכל רוחב, מה תוקן, ומה נדחה ולאן.
4. כשהסקירה רצה על יכולת: `bp map set capability <id> ux=<pass|deferred>`.

## מה חייב להיות נכון בסוף

- הקובץ `spec/ux-review.md` קיים, ואין בו `must` שנכשל.
- לכל מסך שנסקר יש שני צילומים בתיקייה `spec/ux`.
- כל `should` שנדחה מופיע ברשימת "אחר כך" עם סיבה.
