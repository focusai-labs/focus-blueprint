# שלב 03: השאלון

בכל מקום שכתוב `bp`, מריצים `node "${CLAUDE_PLUGIN_ROOT}/scripts/bp.mjs"`.

## למה השלב הזה קיים

שאלון ארוך מעייף, ומי שנשאל שוב על משהו שכבר סיפר מרגיש שלא הקשיבו לו. לכן Claude ממלא מראש כל תשובה שכבר כתובה ברעיון, והסטודנט רק מאשר אותה. את שאר השאלות שואלים בדף, אחת אחרי השנייה, ובכל אחת יש גם "לא יודע עדיין" ו"תחליט אתה". בסוף השלב יש מסמך שאומר מה הוחלט ומי החליט, ומסמך שמתאר מי באמת ישתמש במערכת.

## מה קוראים לפני שמתחילים

- בקובץ המצב `.blueprint/state.json` בודקים שהשלב הנוכחי הוא 3. אם לא, מפנים את הסטודנט ל-`/blueprint`.
- שני החלקים של `spec/idea.md`.
- השאלות בקבצים `${CLAUDE_PLUGIN_ROOT}/data/questions/context.json` ו-`round-a.json`. שאלה שיש לה `when` נשאלת רק כשהתשובה הקודמת מתאימה לתנאי.
- כל העקרונות שמסומנים לשלב 3 בקובץ `${CLAUDE_PLUGIN_ROOT}/data/ux/principles.json`, ובמיוחד R6 עד R11.

## מה עושים

1. מריצים `bp stage start 3`.
2. ממלאים מראש את מה שאפשר. עוברים על השאלות של `context` ושל `a`, ולכל שאלה שהרעיון כבר עונה עליה ושאין לה `prefillable: false`, מריצים `bp prefill <context|a> <qid> value='<json>' quote="<המילים של הסטודנט>"`. הציטוט חייב להיות מתוך `spec/idea.md`, מילה במילה. כשלא בטוחים, לא ממלאים. אומרים לסטודנט בשתי שורות כמה שאלות מולאו, ושבהן הוא רק צריך לאשר או לשנות.
3. פותחים את הדף של הסבב "בשביל מי בונים" עם `node "${CLAUDE_PLUGIN_ROOT}/ui/serve.mjs" --page questionnaire --round context`, ומחכים עם `node "${CLAUDE_PLUGIN_ROOT}/ui/wait.mjs" --name context --until done --timeout 280`. אם הזמן נגמר, מריצים שוב.
4. אם התשובה לשאלה מי ישתמש במערכת היא "הרבה עסקים", ממליצים על עותק נפרד לכל לקוח, כי הפרדה בין עסקים בתוך מערכת אחת היא נושא שלם בפני עצמו. רושמים את הבחירה עם `bp log add kind=track text="<הבחירה והנימוק>" decision=now stage=3`.
5. עושים אותו דבר בסבב הראשון, עם `--round a` ואחר כך `wait.mjs --name round-a`. הדף לא נותן לסיים את הסבב כל עוד יש תשובה שמולאה מראש ועוד לא אושרה.
6. בכל שאלה שבה הסטודנט לחץ "תחליט אתה", Claude בוחר, מנמק ורושם את הבחירה כהכרעה עם `bp ruling add decision="<מה נבחר>" why="<למה>" price="<מה עולה לשנות אחר כך>" stage=3`.
7. כל תשובה של "לא יודע עדיין" רושמים עם `bp pending add <qid>`, והכלי חוזר לשאלה לפני השלב שתלוי בה.
8. רושמים את ההקשר עם `bp state set context='{"payer":"…","approver":"…","users":"…","owner":"…"}'`.
9. כותבים את `spec/decisions.md`, שורה לכל שאלה שנשאלה, עם התשובה, מי החליט ומה הנימוק. בכל שורה כתוב אם התשובה הגיעה מהרעיון ואושרה, או שהשאלה נשאלה בדף.
10. כותבים את `spec/users.md`:
    - התפקידים במערכת (R8).
    - לכל תפקיד, השאלה שמחלקת אותו לקבוצות ולפחות שתי פרסונות (R9). לכל פרסונה יש כרטיס: מי היא, מה היא יודעת, משפט שמאפיין אותה והתכונות שהכי משפיעות על העיצוב.
    - לכל פרסונה לפחות שני תרחישים (R10): מה היא עושה, איפה, מתי, מה קורה סביבה ומה היא צריכה באותו רגע.
    - איך נראה המקום שבו משתמשים במערכת (R11), ומה זה משנה.
11. מראים לסטודנט את שני הקבצים, ומתקנים לפי מה שהוא אומר.

## מה חייב להיות נכון בסוף (ההוכחה)

- הפקודה `bp state get context` מחזירה ארבעה שדות מלאים.
- בקבצים שבתיקייה `.blueprint/ui/answers` אין אף תשובה עם `confirmed: false`.
- בקובץ `spec/decisions.md` יש כל שאלה שרלוונטית לפרויקט.
- בקובץ `spec/users.md` יש לפחות שתי פרסונות לכל תפקיד, ולפחות שני תרחישים לכל פרסונה.

## מה נשאר בתיקייה

- `spec/decisions.md`, `spec/users.md`
- קובצי התשובות `.blueprint/ui/answers/context.json` ו-`round-a.json`, שלא נכנסים ל-Git

## סגירה

1. מריצים את בדיקות ההוכחה ושומרים את הפלט שהן החזירו בפועל.
2. מציגים לסטודנט את ההכרעות של השלב שעוד לא ראה, עם `bp ruling list --unreported --stage 3`, ואחר כך מריצים `bp ruling report --stage 3`. מסבירים כל הכרעה במילים פשוטות: מה נבחר, למה ומה המחיר אם הבחירה שגויה.
3. סוגרים את השלב עם `bp stage done 3 --status <done|done_with_concerns|blocked|needs_context> --note "<מה פתוח>" --proof "<הפלט>"`. כשנשארו שאלות פתוחות שהשלב הבא תלוי בהן, הסטטוס הנכון הוא `done_with_concerns`, וכותבים אותן בהערה.
4. עושים commit בענף `stage-03` עם הודעה בעברית, פותחים PR וממזגים אחרי שהבדיקה עוברת.
5. כותבים את `.blueprint/last-session.md`.
6. אומרים לסטודנט במשפט אחד, בלי לייפות, איך השלב נסגר. אחר כך אומרים בשתי שורות שהשלב הבא הוא מסמך ה-PRD ובחירת המסלול, ושפותחים אותו בשיחה חדשה עם `/blueprint`.
