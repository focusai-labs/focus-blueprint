# שלב 03: השאלון

בכל מקום שכתוב `bp`, מריצים `node "${CLAUDE_PLUGIN_ROOT}/scripts/bp.mjs"`.

## למה השלב הזה קיים

שאלון ארוך שוחק, ושאלה שכבר נענתה מעליבה. לכן Claude ממלא מראש את מה שהרעיון כבר אמר, והסטודנט רק מאשר. כל שאר השאלות נשאלות בדף, אחת אחרי השנייה, ולכל אחת יש "לא יודע עדיין" ו"תחליט אתה". בסוף יש מסמך שאומר מה הוחלט ומי החליט, ומסמך שאומר מי המשתמשים באמת.

## מה קוראים לפני שמתחילים

- בקובץ המצב `.blueprint/state.json`, השלב הנוכחי הוא 3. אם לא, מפנים ל-`/blueprint`.
- הקובץ `spec/idea.md`, שני החלקים שלו.
- השאלות בקבצים `${CLAUDE_PLUGIN_ROOT}/data/questions/context.json` ו-`round-a.json`. שאלה עם `when` נשאלת רק כשהתשובה הקודמת מתאימה.
- בעקרונות `${CLAUDE_PLUGIN_ROOT}/data/ux/principles.json`, כל מה שמסומן לשלב 3, ובמיוחד R6 עד R11.

## מה עושים

1. `bp stage start 3`.
2. **מילוי מראש.** עוברים על השאלות של `context` ושל `a`. לכל שאלה שהרעיון כבר עונה עליה, ושאין לה `prefillable: false`, מריצים `bp prefill <context|a> <qid> value='<json>' quote="<המילים של הסטודנט>"`. הציטוט חייב להיות מתוך `spec/idea.md`, מילה במילה. כשלא בטוחים, לא ממלאים. אומרים לסטודנט בשתי שורות כמה שאלות מולאו, ושבהן הוא רק מאשר או משנה.
3. פותחים את הדף לסבב של בשביל מי בונים: `node "${CLAUDE_PLUGIN_ROOT}/ui/serve.mjs" --page questionnaire --round context`, ומחכים עם `node "${CLAUDE_PLUGIN_ROOT}/ui/wait.mjs" --name context --until done --timeout 280`. כשהזמן נגמר, מריצים שוב.
4. אם התשובה למי ישתמש היא "הרבה עסקים", מסבירים את ההמלצה: עותק נפרד לכל לקוח, כי הפרדה בין עסקים במערכת אחת היא נושא בפני עצמו. רושמים את הבחירה: `bp log add kind=track text="<הבחירה והנימוק>" decision=now stage=3`.
5. אותו דבר לסבב הראשון: `--round a`, ואז `wait.mjs --name round-a`. הדף לא מאפשר לסיים את הסבב כל עוד יש תשובה שמולאה מראש ולא אושרה.
6. עוברים על כל תשובה שבה הסטודנט לחץ "תחליט אתה". בוחרים ומנמקים, ורושמים כל אחת כהכרעה: `bp ruling add decision="<מה נבחר>" why="<למה>" price="<מה עולה לשנות אחר כך>" stage=3`.
7. כל "לא יודע עדיין" נרשם: `bp pending add <qid>`. הכלי חוזר לשאלה לפני השלב שתלוי בה.
8. רושמים את ההקשר: `bp state set context='{"payer":"…","approver":"…","users":"…","owner":"…"}'`.
9. כותבים את `spec/decisions.md`: שורה לכל שאלה שנשאלה, עם התשובה, מי החליט, והנימוק. כל שורה אומרת אם התשובה הגיעה מהרעיון ואושרה, או שנשאלה בדף.
10. כותבים את `spec/users.md`:
    - התפקידים (R8).
    - לכל תפקיד, השאלה שמחלקת אותו ולפחות שתי פרסונות (R9). לכל פרסונה כרטיס: מי היא, מה היא יודעת, משפט שמאפיין אותה, והתכונות שהכי משפיעות על העיצוב.
    - לכל פרסונה לפחות שני תרחישים (R10): מה היא עושה, איפה, מתי, מה יש סביב, ומה היא צריכה באותו רגע.
    - איך נראה המקום שבו משתמשים (R11), ומה זה משנה.
11. מראים לסטודנט את שני הקבצים, ומתקנים לפי מה שהוא אומר.

## מה חייב להיות נכון בסוף (ההוכחה)

- הפקודה `bp state get context` מחזירה ארבעה שדות מלאים.
- בקבצים שבתיקייה `.blueprint/ui/answers` אין אף תשובה עם `confirmed: false`.
- הקובץ `spec/decisions.md` מכיל כל שאלה שחלה על הפרויקט.
- הקובץ `spec/users.md` מכיל לפחות שתי פרסונות לכל תפקיד, ולפחות שני תרחישים לכל פרסונה.

## מה נשאר בתיקייה

- `spec/decisions.md`, `spec/users.md`
- קובצי התשובות `.blueprint/ui/answers/context.json` ו-`round-a.json`, שלא נכנסים ל-Git

## סגירה

1. מריצים את בדיקות ההוכחה, ושומרים את הפלט האמיתי.
2. מציגים את ההכרעות של השלב: `bp ruling list --unreported --stage 3`, ואז `bp ruling report --stage 3`. כל הכרעה מוצגת במילים פשוטות: מה נבחר, למה, ומה המחיר אם זה שגוי.
3. סוגרים: `bp stage done 3 --status <done|done_with_concerns|blocked|needs_context> --note "<מה פתוח>" --proof "<הפלט>"`. כשנשארו שאלות פתוחות שהשלב הבא תלוי בהן, הסטטוס הכן הוא `done_with_concerns`, והן כתובות בהערה.
4. עושים commit בענף `stage-03` עם הודעה בעברית, PR, ומיזוג אחרי שהבדיקה עוברת.
5. כותבים את `.blueprint/last-session.md`.
6. אומרים לסטודנט בשורה אחת כנה איך השלב נסגר. אחר כך שתי שורות: הבא בתור הוא מסמך ה-PRD ובחירת המסלול, בשיחה חדשה עם `/blueprint`.
