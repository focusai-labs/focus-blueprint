# שלב 15: מסירה

בכל מקום שכתוב `bp`, מריצים `node "${CLAUDE_PLUGIN_ROOT}/scripts/bp.mjs"`.

## למה השלב הזה קיים

מסירה שהיא רק קובץ שנשלח נגמרת בלקוח שמתקשר בכל פעם. מסירה טובה נבדקת: מי שיפעיל את המערכת מבצע לבד את המשימות הנפוצות, ואיפה שהוא נתקע, מתקנים את המדריך או את המערכת.

## מה קוראים לפני שמתחילים

- בקובץ המצב `.blueprint/state.json`, השלב הנוכחי הוא 15, ההקשר בשדה `context`, ואיפה הכל נמצא בשדה `where`.
- התבנית `${CLAUDE_PLUGIN_ROOT}/templates/docs/handover-<client|org|self>.md`, לפי ההקשר.

## מה עושים

1. מריצים `bp stage start 15`.
2. כותבים את מסמכי המסירה מהתבנית לתיקייה `docs`: מדריך למי שיפעיל, מסמך למי שיפתח אחר כך, ורשימת חשבונות. ברשימה יש שמות של שירותים ושל חשבונות, ואף סיסמה או מפתח.
3. בוחרים עם הסטודנט שלוש משימות שמי שיפעיל עושה לבד, למשל להוסיף לקוח, לשנות נוסח של תזכורת, ולבדוק מי לא שלח החודש.
4. מי שיפעיל מבצע אותן מהמדריך, בלי עזרה. הסטודנט מביא את מה שקרה. כותבים ב-`docs/handover-test.md`, לכל משימה, אם היא הצליחה ואיפה הוא נתקע.
5. מתקנים את המדריך או את המערכת, ובודקים שוב את מה שנתקע.
6. שומרים את הפרויקט בפרופיל האישי: `bp profile set projects='[…]'` עם הפרויקט, ואת מערכת העיצוב: `bp profile set designSystems='[…]'`, כדי שאפשר יהיה להשתמש בהם שוב.
7. **הדוח החודשי.** כשמבקשים, מפיקים את `docs/report-<yyyy-mm>.md` מהתבנית `${CLAUDE_PLUGIN_ROOT}/templates/docs/report-<client|org|self>.md`. את העלות בודקים בחשבונות של הספקים, ולא לפי מה שהמודל דיווח. בודקים גם את המשפט שאומר איך נדע שזה עובד, מה-PRD.

## מה חייב להיות נכון בסוף (ההוכחה)

- בקובץ `docs/handover-test.md` יש שלוש משימות, ולכל אחת התוצאה.
- ברשימת החשבונות אין אף סיסמה, מפתח או טוקן.
- כל משימה שנתקעה תוקנה ונבדקה שוב.

## מה נשאר בתיקייה

- מסמכי המסירה, וקובץ הבדיקה `docs/handover-test.md`
- הפרויקט ומערכת העיצוב בפרופיל האישי

## סגירה

1. מריצים את בדיקות ההוכחה, ושומרים את הפלט האמיתי.
2. מציגים את ההכרעות של השלב: `bp ruling list --unreported --stage 15`, ואז `bp ruling report --stage 15`.
3. סוגרים: `bp stage done 15 --status <done|done_with_concerns|blocked|needs_context> --note "<מה פתוח>" --proof "<הפלט>"`.
4. עושים commit בענף `stage-15` עם הודעה בעברית, PR, ומיזוג אחרי שהבדיקה עוברת.
5. כותבים את `.blueprint/last-session.md`.
6. אומרים לסטודנט בשורה אחת כנה איך השלב נסגר. אחר כך שורה אחת: התהליך הושלם, וכל שינוי מכאן עובר דרך `/blueprint`.
