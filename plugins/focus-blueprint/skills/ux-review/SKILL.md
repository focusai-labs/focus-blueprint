# סקירת UX

בכל מקום שכתוב `bp`, מריצים `node "${CLAUDE_PLUGIN_ROOT}/scripts/bp.mjs"`.

גם מסך יפה יכול להיות קשה לשימוש. מה שאפשר למדוד, סקריפט מודד, ואת השאר Claude בודק על צילומי מסך, לפי רשימת עקרונות. כל העקרונות ברמה `must` צריכים לעבור לפני שאדם אמיתי רואה את המסך.

## מה סוקרים

- אם לא נאמר אחרת, סוקרים את כל המסכים שבמפה `.blueprint/map.json`. בשלב 7 נכנסים אליהם דרך הקישור ל-mockup או דרך `file://`, ובשלבים 11 עד 13 דרך הכתובת החיה.
- כשהסקירה רצה מתוך יכולת בשלב 12, סוקרים רק את המסכים של היכולת הזאת.

## איך סוקרים כל מסך

1. קוראים עם הכלי Read את הקובץ `${CLAUDE_PLUGIN_ROOT}/scripts/ux-check.browser.js`. כל הטקסט שלו הוא פונקציה אחת.
2. בכלי ה-MCP של Playwright מריצים `browser_navigate` לכתובת, `browser_resize` לרוחב 1280 ולגובה 800, ואחר כך `browser_evaluate` עם הטקסט של הקובץ בשדה `function`, ושומרים את התוצאה.
3. עושים אותו דבר ברוחב 390 ובגובה 844. בדיקה שמסומנת לטלפון בלבד או למחשב בלבד מדלגת על עצמה ברוחב השני.
4. מצלמים את המסך בשני הרוחבים עם `browser_take_screenshot`, ושומרים את הצילומים בתיקייה `spec/ux`.
5. עוברים על כל עיקרון בקובץ `${CLAUDE_PLUGIN_ROOT}/data/ux/principles.json` שהשדה `check` שלו הוא `review`, ושהשלב הנוכחי נמצא ברשימת השלבים שלו. כל עיקרון כזה שופטים לפי הצילומים, ונותנים פסק דין בשורה אחת: עבר, נכשל או אזהרה, ולמה.
6. כשאין Playwright MCP, או שהדפדפן תפוס, אומרים את זה במפורש, והסקירה לא נחשבת כאילו עברה.

## מה עושים עם התוצאות

1. כל `must` שנכשל, בבדיקה האוטומטית או בסקירה, מתקנים מיד ובודקים את המסך שוב, עד שאין אף `must` שנכשל.
2. כל `should` שלא מתקנים עכשיו נכנס לרשימת "אחר כך" עם הסיבה, בעזרת `bp map later add "<העיקרון, המסך והסיבה>" --stage <השלב>`.
3. כותבים את `spec/ux-review.md`, עם טבלה של העיקרון, הרמה, אם הוא נבדק אוטומטית או בסקירה, התוצאה בכל רוחב, מה תוקן ומה נדחה ולאן.
4. כשהסקירה רצה על יכולת, רושמים את התוצאה עם `bp map set capability <id> ux=<pass|deferred>`.

## מה חייב להיות נכון בסוף

- הקובץ `spec/ux-review.md` קיים, ואין בו `must` שנכשל.
- לכל מסך שנסקר יש שני צילומים בתיקייה `spec/ux`.
- כל `should` שנדחה מופיע ברשימת "אחר כך" עם סיבה.
