# בדיקות ההתקנה בשלב 1

בכל מקום שכתוב `bp`, מריצים `node "${CLAUDE_PLUGIN_ROOT}/scripts/bp.mjs"`.

## הגרסה של Claude Code

1. בודקים את הגרסה של Claude Code, כי בגרסה ישנה מ-2.1.277 חלק מהכללים והבדיקות של הכלי לא עובדים כמו שצריך.
2. ב-VS Code הגרסה של Claude Code היא הגרסה של התוסף Claude Code, ולכן מבקשים מהסטודנט לפתוח את חלון התוספים (Cmd+Shift+X ב-Mac, Ctrl+Shift+X ב-Windows) ולכתוב איזו גרסה מופיעה ליד התוסף. מי שעובד בטרמינל מריץ `claude --version`. הגרסה של הפקודה `claude` בטרמינל לא תמיד זהה לגרסה של החלון ב-VS Code, כי התוסף מביא עותק משלו.
3. כשהגרסה נמוכה מ-2.1.277, הסטודנט מעדכן לפני שממשיכים. ב-VS Code מעדכנים את התוסף בחלון התוספים, ובטרמינל לפי https://code.claude.com/docs/en/setup, שקוראים דרך `/focus-blueprint:docs-verify`. אחרי העדכון פותחים שיחה חדשה.

## בדיקה שלא הצליחה לרוץ

כשהבדיקה של Playwright MCP או של superpowers מחזירה null, זה אומר שהבדיקה לא הצליחה לרוץ, ולא שהם חסרים. בודקים שוב בדרך אחרת, את Playwright עם `bp mcp list` ואת superpowers עם `claude plugin list`. כשגם זה לא עובד, למשל ב-VS Code בלי Claude Code בטרמינל, מבקשים מהסטודנט לפתוח את `/mcp` ואת `/plugins` בחלון של Claude Code ולכתוב מה מופיע שם.

## בלי GitHub

כשאין לסטודנט חשבון GitHub, או שהחיבור לא מצליח גם אחרי `gh auth login`, ממשיכים בלי GitHub, כדי שהסטודנט לא ייתקע:

1. בצעד 9 עושים רק את ה-commit הראשון על main, בלי ליצור מאגר ב-GitHub, ומדלגים על צעד 10.
2. רושמים את הפער עם `bp ruling add decision="הפרויקט עובד בינתיים בלי GitHub" why="<הסיבה>" price="אין גיבוי בענן ואין בדיקה ב-CI עד שמתחברים" stage=1`.
3. סוגרים את השלב עם הסטטוס `done_with_concerns`, וכותבים בהערה שחסר GitHub.
4. אומרים לסטודנט במשפט אחד שאפשר להמשיך, ושאת החיבור ל-GitHub צריך להשלים לפני שלב 11, שבו המערכת עולה לאוויר.
